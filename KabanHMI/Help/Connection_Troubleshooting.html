PLC connection troubleshooting

The HMI shows this warning when a controller stops answering. Values already on screen are the last ones read and are not being refreshed.

Before anything else: the machine may still be moving. The HMI has lost sight of the controller, not control of the machine. Treat the machine as live until you have checked it.

C01 — No driver configured for this station

The station exists in the program but nothing was set up to talk to it.

  1. Open HMI Settings → PLC Connection.
  2. Check the Driver column for this controller. An empty or wrong driver is the usual cause after a settings import.
  3. Set the driver, save, and restart the program.

C02 — Link not open

The program tried to open the link and could not. Nothing has been reached.

  1. Check the controller has power and its run lamp is on.
  2. Check the network cable at both ends, and the switch port lamp.
  3. Check the Address on the PLC Connection page matches the controller (e.g. 192.168.1.31).
  4. From the panel PC, ping that address. No reply means the fault is in the network, not in the HMI.
  5. For a serial or USB driver, check the cable and that no other program (GX Works, a configurator) is holding the port.

C03 — Link open but no reply

The connection exists but reads are failing. This is the one that most often means a cable half out or a controller that has stopped.

  1. Check the controller is in RUN, not STOP or an error state.
  2. Check its own error lamps and, if fitted, its display code.
  3. Check the network for a loose plug or a switch that has lost power.
  4. If the controller was recently reprogrammed, check the device addresses the HMI reads still exist in the new program.

C04 — Unexpected reply

Something answered, but not in the form expected.

  1. Check the Driver matches the controller make - a Mitsubishi driver pointed at a Siemens controller reaches it and fails here.
  2. Check the station number on the PLC Connection page.
  3. Check the PLC program version in the State column against the version this machine expects.

After the connection returns

The warning clears by itself once reads succeed again. Values resume updating immediately; nothing needs to be acknowledged.
