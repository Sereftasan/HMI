minimal structural change, so every change can be reviewed line by line. No
project and no file was removed; only dead code inside files. Every fix has a
comment at the change explaining *why*. The six UI requests of 23 September are
included (section 4).

## 1. Please review first: changes that affect how the machine behaves

| # | Change | Why | Where |
|---|---|---|---|
| 1 | **Jog (momentary) bits are always released.** Released on mouse-up *and* on loss of mouse capture, hide, disable, being moved or disposed, and when the button's enable condition drops (manual mode left, logout, station lost). The release goes through the monitoring driver, which no login level can block. A right-click no longer starts a jog. | The bit was cleared only on mouse-up, through the permission-gated driver. A message box taking the mouse, the button being hidden by its visibility condition, a page change or a logout mid-press left the axis jogging. | `ButtonHMI.cs` |
| 2 | **Alarms are evaluated per station.** Each alarm is read from its own controller and evaluated against that controller's fresh data. | All alarm addresses were read from station 1. H500 and H800 alarms (stations 3 and 4) use the same M801... addresses as FA2010, so they were raised and cleared by FA2010's bits - false alarms and missed alarms. | `PlcScanner.cs`, `AlarmManager.cs` |
| 3 | **Conditions are read from the station they are registered on**, and fail closed when that station has no data. | SB3012's alarm reset button uses `MillingUnitIsBack` (X25 on PLC2); it was read from PLC1. | `PlcScanner.cs` |
| 4 | **F12 (PLC memory monitor) now needs Admin**, like its menu entry. The caption-bar button on simulated bench builds is unchanged. | The monitor writes any device of any station, bypassing every control's own level and interlocks; F12 opened it for anyone at the panel. | `MainForm.cs` |
| 5 | **Page security is checked per page.** | It was keyed by class, and every multi-machine page is a `SettingsScreen`, so all of them shared the level of whichever group registered last. Back/Forward could open Machine Parameters without Maintenance, or refuse Home. | `MainForm.cs` |

| 6 | **Each machine resets its alarms with ITS OWN bit.** The alarm menu's "Reset (n) Active Alarms" pulses it (on, then off after 300 ms, on the machine's own controller), then clears the list; the Alarms page's Reset button is momentary on the same bit. The bit is declared in the machine's module, like the program-version device (`PlcManager.SetAlarmResetDevice`): **FA2010 PLC1 = M102**, as you said. No other machine has one declared yet, so their Reset button is **grey and says so**, and the menu clears only the list (with a message that the machine was not reset). **Before, every machine's Alarms page pulsed M102** - on H500 that is `MAN_Lubrication`. | You told me M102 is FA2010 PLC1's reset only. Nothing is pulsed on a guess. | `PlcManager.cs`, `FA2010Module.cs`, `AlarmReset.cs`, `MachineAlarmScreen.cs` |
| 7 | **Jog buttons never ask for confirmation**, as you said - holding the button is the confirmation. A button whose actions are all momentary now does nothing on Click; with `ConfirmationNeeded` set it used to show "Are you sure?" after the jog had already run. | | `ButtonHMI.cs` |

## 4. The six UI requests (23 September)

1. **Back / Forward** load reliably. A step is now a *location* - the page plus the tab chosen on every tab strip inside it (machine, sub-page) - and replaying it restores all of it. The machine strip now marks the machine actually on screen (it always marked the main machine). Re-choosing the place you are on adds no step; login and language rebuilds add none. Test: `tools/nav_test/History.cs` (8 of its checks fail on the original).
2. **AxisUnitHMI position** is drawn like the Axis Settings row: black, bold Segoe UI 12 on the read-only grey - and since 24 September **every function unit's** position too (the red readout remains as `PositionStyle = Readout` for a page that wants it). On an axis error only the display's border blinks red.
3. **Same width.** The "?" used to sit on the side lines and took half a badge of width from each side with an error bit - so an axis unit (always one error bit) rendered narrower than a function unit of the same size. The frame now always uses the full width, and the axis unit's slots scale with its width (at the generated 248 px they are exactly the Axis Settings widths). Both default to 360 x 64.
4. **"?" on the top frame line, right end**, red and blinking while the error is set; the "i" moves just left of it. The border of what failed blinks red: the button of the movement that failed (cylinder units, ErrorA -> button A, ErrorB -> button B) or the position display (axis units).
5. **Hand cursor everywhere.** Every window is swept once when it appears and every container is watched for controls added later; menus and toolbars show the hand over enabled items and the arrow over headings, separators and disabled entries. The caption-bar minimise/maximise/close buttons now have it too. Disabled controls still show the arrow.
6. **Manual tab removed.** HMI Settings > About now shows the program, its version and the machines mounted, and a button **Open the HMI manual** that opens `Help/Kaban_HMI_Manual.<language>.html` in the browser (the language on screen, then English). The English manual is included, with drawings of the screen and of a unit; every machine project copies it to `bin\...\Help`. To translate it, copy it as `Kaban_HMI_Manual.tr.html` beside it.

## 4c. The requests of 24 September (evening)

1. **M102 is FA2010 PLC1's alarm reset only** - each machine now declares its own reset bit (section 1, row 6); the other machines' bits are still to be set (see "Needs your decision").
2. **PLC Monitor fixes** - the causes:
   - *A device added to an empty tab went into the tab before it, and deleting a tab deleted the one before it too.* The list of tabs and the tab strip were matched by position, and `TabPages.Insert` on a strip whose window does not exist yet appends at the END whatever position it is given - so the two orders parted after a few new tabs. Each page now carries its tab (`Tag`), the tab on display is read from the page itself, the strip's window is created before a page is inserted, and the list is re-read from the strip after every change.
   - *No tooltips.* The monitor used the program's shared tooltip, which belongs to the main window and never shows over another window. It has its own now. **Export** (📤) and **Import** (📥) have their own buttons.
   - *A right-click after selecting several rows left only one selected* - it set the current cell, which clears a multi-selection. A right-click on a selected row now leaves the selection alone; Copy and Remove take every selected row.
3. **Tabs**: a new tab goes **before the tab on display**; **every tab can be deleted** (adding a device then makes a "Main" for it; the file remembers there are none); **drag a tab** along the strip to move it several places at once (it moves as the pointer passes the others; saved on release).
4. **Columns**: fixed widths each (no column stretched to the edge, so narrowing the last one leaves space instead of widening its neighbour); drag a heading to re-order; the widths and order are the same on every tab and kept (`Monitor\Columns.cfg`). **Click a heading to sort**, again to reverse (arrow in the heading). Under comment lines each section is sorted on its own and keeps its heading; addresses in the PLC's order (M2 before M10, X in octal, W in hex); values numerically, unread ones last.
5. The **"LIVE PLC - a value typed here..." banner is removed**; writes to a real PLC are still in the audit log.

## 7. Noticed, not changed (kept for later)

- MX Component: when a batch read fails, the per-address fallback (about 15 ms each) can exceed the 1 s wait on a page with many addresses, so one invalid address can make a station flap. Needs the hardware to tune.
- `Kaban.Core.csproj` lists `Data/Schema.sql`, which was not in the upload; Visual Studio fails if it is missing on disk.
- The machine executables have no App.config binding redirects, while Kaban.Core uses System.Text.Json 10 and its nine dependencies - worth confirming on a clean PC.
- `SimulationMonitorForm` reads simulated memory by reflection every 250 ms; `FunctionUnitHMI` checks its help files on disk at every property set in the designer; `PlcAddressHelper.OffsetAddress` compiles a regex per call. All small.
- `BoundedDriver.Dispose` disposes the wrapped driver on the caller's thread while its worker may still be using it (it also unblocks a stuck socket, which is useful - left as is).
