# Kaban HMI - code review, 24 September 2026

Scope agreed: **conservative** - fix bugs, leaks and performance problems with
minimal structural change, so every change can be reviewed line by line. No
project and no file was removed; only dead code inside files. Every fix has a
comment at the change explaining *why*. The six UI requests of 23 September are
included (section 4).

**Install:** unzip `HMI_Fixed.zip` **over your current HMI folder**. It holds every
text file of the solution; the binary files that were never in the uploaded
documents (the MX Component interop DLL, the two supplier PDFs, the DXF, the PNG
and ICO resources) are not in it, so extracting over the existing folder keeps
them. `CHANGED_FILES.txt` lists the 58 files that differ from what was uploaded (A = added, M = modified; nothing was deleted).

**Checked:** the whole solution builds (Mono xbuild, all 8 executables, no new
warnings, three old ones gone); `tools/check_projects.py` reports OK; the test
suites were run before and after (section 6). Six new test programs cover the
fixes; each was also run against the original build and fails there on the bug
it guards against.

## 1. Please review first: changes that affect how the machine behaves

| # | Change | Why | Where |
|---|---|---|---|
| 1 | **Jog (momentary) bits are always released.** Released on mouse-up *and* on loss of mouse capture, hide, disable, being moved or disposed, and when the button's enable condition drops (manual mode left, logout, station lost). The release goes through the monitoring driver, which no login level can block. A right-click no longer starts a jog. | The bit was cleared only on mouse-up, through the permission-gated driver. A message box taking the mouse, the button being hidden by its visibility condition, a page change or a logout mid-press left the axis jogging. | `ButtonHMI.cs` |
| 2 | **Alarms are evaluated per station.** Each alarm is read from its own controller and evaluated against that controller's fresh data. | All alarm addresses were read from station 1. H500 and H800 alarms (stations 3 and 4) use the same M801... addresses as FA2010, so they were raised and cleared by FA2010's bits - false alarms and missed alarms. | `PlcScanner.cs`, `AlarmManager.cs` |
| 3 | **Conditions are read from the station they are registered on**, and fail closed when that station has no data. | SB3012's alarm reset button uses `MillingUnitIsBack` (X25 on PLC2); it was read from PLC1. | `PlcScanner.cs` |
| 4 | **F12 (PLC memory monitor) now needs Admin**, like its menu entry. The caption-bar button on simulated bench builds is unchanged. | The monitor writes any device of any station, bypassing every control's own level and interlocks; F12 opened it for anyone at the panel. | `MainForm.cs` |
| 5 | **Page security is checked per page.** | It was keyed by class, and every multi-machine page is a `SettingsScreen`, so all of them shared the level of whichever group registered last. Back/Forward could open Machine Parameters without Maintenance, or refuse Home. | `MainForm.cs` |

**Not changed, needs your decision:**
- The caption-bar alarm menu entry "Reset (n) Active Alarms" only *acknowledges* the list on screen (it does not pulse M102); an alarm whose cause remains comes straight back. The PLC reset is the Reset button on the Alarms page. The new manual describes it this way. Say if the menu should pulse M102 as well.
- `ConfirmationNeeded` is not applied to Momentary actions (the confirmation runs on Click, after the jog has already happened).
- `ProfilesScreen` connects to PostgreSQL with the fixed credentials `kaban/kaban`.

## 2. Bugs fixed

| Where | Problem | Fix |
|---|---|---|
| `HmiUtilities.cs` (AuditLogger), `LogSettingsControl.cs` | The log viewer and "Export today" read `yyyy-MM-dd.txt`; the logger writes `HmiAudit_yyyy-MM-dd.txt`. The viewer was always empty, export always said "no log". The viewer's read also locked the file, so a line logged meanwhile was lost. | One `TodayFile`; the viewer reads with shared access; export failures are reported instead of crashing. |
| `AlarmDefinitionLoader.cs`, `AlarmSettingsControl.cs` | Alarm Settings **Save never saved** - the Load overload every module uses never recorded the path ("Nothing to save"). With one path it would have written all machines' alarms into one file, matched by address (FA2010/H500/H800 share M801...), dropped each entry's `Comment`, and escaped Turkish/Russian text as `\uXXXX`. | Each entry remembers its file and module; each page saves only its machine's file, matched by scoped code; `Comment` kept; readable UTF-8. |
| `Kaban.Machines.MD3020/Alarms.json` | Old format (Code/Address/Description...), skipped by the loader: MD3020 had no alarms. | Converted, texts taken from MD3020's `Translations.csv`. The texts ("H800: unit fault") look copied from another machine - please check. |
| `NumpadForm.cs`, `NumericInputHMI.cs`, `InputForm.cs` | On a Windows with decimal comma (TR, DE, RU, IT, ES) every decimal entry was refused; the write path parsed with thousands separators allowed ("12.5" would become 125); a hex field was handed its decimal value (255 read back as 0x255). | The keypad works in "." decimal on every Windows; hex fields get hex; the text dialog no longer accepts thousands separators. |
| `ConnectionMonitor.cs` | Local time: when the clocks go back in autumn a dead station counted as live for up to an hour. Read from two threads without a lock (DateTime can be half-written in a 32-bit process). | UTC; state changes under a lock; each change announced once. |
| `NavigationHistory.cs`, `SettingsScreen.cs`, `MainForm.cs`, `MachineSelectorStrip.cs` | Back/Forward (request 1). | See section 4. |
| `UserStore.cs`, `UserSettingsControl.cs` | A `;` in a user name broke Users.dat on the next start; the last Admin could be demoted; a damaged account threw out of the login. | Names validated; the last Admin can be neither demoted nor removed; a damaged account is a failed login. |
| `DeltaModbusTcp.cs` | A write the device refused (Modbus exception) was reported as success. | Returns -1 (the link itself stays healthy). |
| `TroubleshootingCatalog.cs` | `Resolve(fileName)` shadowed `Resolve(code)`: a one-argument call returned a path string instead of documents - which is why four help tests no longer compiled. | File resolver renamed `ResolveLanguageFile`. |
| `MainForm.cs` | Embedded images were returned after their stream was disposed (GDI+ "generic error" risk). | A copy is returned. |
| `PlcScanner.cs` | The scan worker could throw out of a thread-pool thread (ends the process) or leave `_scanBusy` set (screen stops updating). | Guarded. |
| `MainForm.cs` | The connection poll kept running during close and could re-open a station after `DisconnectAll`. | Stopped first. |

## 3. Leaks and performance

| Where | Problem | Fix |
|---|---|---|
| `BoundedDriver.cs`, `StaWorker.cs` | One kernel event per PLC call, never disposed - thousands of handles a minute per station at the 100 ms scan. | Disposed by whichever side finishes last. |
| `BaseNumericHMI.cs`, `ButtonHMI.cs`, `LabelHMI.cs` | Subscribed to the static `LanguageChanged` with lambdas that could never be removed (BaseNumericHMI's Dispose removed a *different* delegate): every field, button and label ever created stayed alive with its page. | Named handlers removed on dispose (test: 160 controls leave 0 subscriptions; the original left 160). |
| `MachineAlarmScreen.cs` | Subscribed to the static alarm list with a lambda. | Removed on dispose. |
| `UiStyle.cs`, `MainForm.cs`, `MachineAlarmScreen.cs`, `AlarmHelpBadge.cs` | Every dropdown (connection, alarms, login, language, close, alarm help, column chooser) was built per click and never disposed; each made a new Font. | The previous menu of the same button is disposed when the next opens (disposing on Closed would run before the item's Click); one shared menu font. |
| `ButtonHMI.cs`, `SettingsScreen.cs`, `FunctionUnitHMI.cs`, `AlarmHelpBadge.cs` | New Font per active-page toggle, per tab switch, per readout resize (plus rejected font candidates), per unit caption, per badge paint; GraphicsPath not disposed on every resize. | Shared or cached fonts; paths disposed. |
| `PlcScanner.cs` | Version device read on every 100 ms scan (an extra round trip per station). | Once a second. |
| `AlarmManager.cs` | One list refresh and one event per alarm - an E-stop repainted every bound grid a dozen times. | One per scan. |
| `MachineAlarmScreen.cs` | Help column probed the disk several times per cell per repaint. | 2-second cache. |
| `MainForm.cs` | Blinking login icon re-tinted pixel by pixel on every paint. | Cached. |
| `PlcScanner.cs` | `Enum.GetValues` plus boxing `HasFlag` for every condition of every control on every scan. | Flags cached, bit tests. |
| `SafeFile.cs` (new), `UserStore`, `UnitManager`, `PlcConnectionSettings`, `SettingsMigration`, `AlarmDefinitionLoader` | A power cut during a save left an empty or cut-off file (no users, no PLC addresses). | Written to `.tmp`, flushed, swapped in. |
| `HmiDatabase.cs` | Npgsql's 15 s connect timeout, checked from the UI thread. | 3 s. |

## 4. The six UI requests (23 September)

1. **Back / Forward** load reliably. A step is now a *location* - the page plus the tab chosen on every tab strip inside it (machine, sub-page) - and replaying it restores all of it. The machine strip now marks the machine actually on screen (it always marked the main machine). Re-choosing the place you are on adds no step; login and language rebuilds add none. Test: `tools/nav_test/History.cs` (8 of its checks fail on the original).
2. **AxisUnitHMI position** is drawn like the Axis Settings row: black, bold Segoe UI 12 on the read-only grey. Function units keep their red-on-black readout. On an axis error only the display's border blinks red.
3. **Same width.** The "?" used to sit on the side lines and took half a badge of width from each side with an error bit - so an axis unit (always one error bit) rendered narrower than a function unit of the same size. The frame now always uses the full width, and the axis unit's slots scale with its width (at the generated 248 px they are exactly the Axis Settings widths). Both default to 360 x 64.
4. **"?" on the top frame line, right end**, red and blinking while the error is set; the "i" moves just left of it. The border of what failed blinks red: the button of the movement that failed (cylinder units, ErrorA -> button A, ErrorB -> button B) or the position display (axis units).
5. **Hand cursor everywhere.** Every window is swept once when it appears and every container is watched for controls added later; menus and toolbars show the hand over enabled items and the arrow over headings, separators and disabled entries. The caption-bar minimise/maximise/close buttons now have it too. Disabled controls still show the arrow.
6. **Manual tab removed.** HMI Settings > About now shows the program, its version and the machines mounted, and a button **Open the HMI manual** that opens `Help/Kaban_HMI_Manual.<language>.html` in the browser (the language on screen, then English). The English manual is included, with drawings of the screen and of a unit; every machine project copies it to `bin\...\Help`. To translate it, copy it as `Kaban_HMI_Manual.tr.html` beside it.

## 7. Noticed, not changed (kept for later)

- MX Component: when a batch read fails, the per-address fallback (about 15 ms each) can exceed the 1 s wait on a page with many addresses, so one invalid address can make a station flap. Needs the hardware to tune.
- `Kaban.Core.csproj` lists `Data/Schema.sql`, which was not in the upload; Visual Studio fails if it is missing on disk.
- The machine executables have no App.config binding redirects, while Kaban.Core uses System.Text.Json 10 and its nine dependencies - worth confirming on a clean PC.
- `SimulationMonitorForm` reads simulated memory by reflection every 250 ms; `FunctionUnitHMI` checks its help files on disk at every property set in the designer; `PlcAddressHelper.OffsetAddress` compiles a regex per call. All small.
- `BoundedDriver.Dispose` disposes the wrapped driver on the caller's thread while its worker may still be using it (it also unblocks a stuck socket, which is useful - left as is).
